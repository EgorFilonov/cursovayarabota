# Правила работы над проектом

Соглашения для ИС «Овощной магазин». Проект на Python: PEP 8 и Ruff, параметр `self`, docstring.

Этот issue не закрывается. В pull request для него нельзя писать `Fixes`, `Closes` и `Resolves`.

## 1. Стиль именования

| Элемент | Стиль | Пример |
| --- | --- | --- |
| Модуль и пакет | snake_case | `vegetable_store` |
| Класс | PascalCase | `Batch` |
| Функция и метод | snake_case | `create_sale` |
| Переменная и параметр | snake_case | `batch_id` |
| Непубличный атрибут | префикс `_` | `_connection` |
| Константа | UPPER_CASE | `SELLER_ROLE` |
| Метод экземпляра | первый параметр `self` | `def save(self)` |

Имена в коде на английском. Тексты для пользователя на русском.
Импорты тремя группами: стандартная библиотека, сторонние пакеты, модули проекта.

## 2. Параметр `self`

У метода экземпляра первый параметр всегда называется `self`. Через него читаются атрибуты и вызываются другие методы. `self` не переименовывается.

```python
class BatchBook:
    def __init__(self, connection: sqlite3.Connection) -> None:
        self._connection = connection

    def leftover(self, batch_id: int) -> int:
        return self._read_left(batch_id)
```

## 3. Документирование

У публичных модулей, классов и функций есть docstring в формате Google. Его понимает Sphinx через Napoleon.

Обязательно: первая строка — что делает объект, `Args` у параметров кроме `self`, `Returns`, если есть результат, `Raises`, если вызывающий код должен поймать исключение.

Краткое описание эндпоинта попадает в Swagger на `/docs`.

## 4. Сообщения коммитов

Формат Conventional Commits: `тип: описание` на русском, без точки в конце.

Типы: `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore`, `ci`, `build`.

## 5. Ветки и pull request

- Основная ветка — `master`. После первого коммита прямой push в неё не делается.
- Каждая задача начинается с issue.
- Ветка от `master` называется `feature/<номер issue>`.
- Результат сдаётся pull request в `master`.
- Ревьюер — MarinaPaley. Приглашение пока не отправляется.
- Одна задача — один pull request.
- Перед PR локально проходят `ruff check .` и `pytest`.

## 6. Прочие договорённости

- Документация репозитория — только Markdown.
- Текст пояснительной записки лежит в папке `КР` в формате docx.
- `.docx` помечен в `.gitattributes` как бинарный файл.
- Секреты, `.venv` и файл SQLite в репозиторий не коммитятся.
- Зависимости перечислены в `requirements.txt`.
- Роль в запросе передаётся заголовком `X-Role`: `seller` или `merchandiser`.
- Сборка и тесты выполняет GitHub Actions: Python 3.12, Ruff, pytest, SQLite.
